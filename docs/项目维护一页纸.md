## 五、出问题先看这里（决策树）

```
用户说「打不开」
├─ kebiaoplan.cn → 可能是备案拦截 → 让用户先用 http://122.51.12.86
├─ IP 也打不开 → pm2 status → 若 stopped：pm2 restart kebiaoplan
├─ 502/504 → pm2 logs kebiaoplan --lines 50
└─ 纯文本无样式 → 服务器上 cd /var/www/plan && git pull && npm run build && pm2 restart

用户说「登录失败」
├─ 仅一人 → 可能密码错 / 本地缓存 → 换浏览器试
├─ 全部人 → Supabase 是否 Paused → 控制台 Restore
└─ 500 错误 → pm2 logs + 检查 .env 里 DATABASE_URL、AUTH_SECRET

用户说「进度丢了」
├─ 是否登录同一账号、同一浏览器
├─ Supabase → user_courses 表查该 user_id 是否还有数据
├─ 数据在 → 前端/同步 bug，修代码，别动库
└─ 数据不在 → 查备份恢复，别慌删表

用户说「某 B 站课解析失败」
└─ 多半是 B 站限流/单课问题 → 换链接试，非全站挂
```

## 六、服务器常用命令（腾讯云 WebShell）

```bash
# 进入项目
cd /var/www/plan

# 看进程
pm2 status
pm2 logs kebiaoplan --lines 50

# 重启（改 .env 或 deploy 后）
pm2 restart kebiaoplan

# 拉最新代码并部署
git pull origin main
npm install --legacy-peer-deps
npm run build
pm2 restart kebiaoplan

# 本机应用是否活着
curl http://127.0.0.1:3000/api/health

# Nginx 是否转到应用
curl http://127.0.0.1/api/health

# 内存
free -h
```

## 七、Supabase 休眠 / 恢复

**现象：** 所有人登录失败、同步失败，控制台显示 **Paused**

**数据：** 113+ 用户 **不会丢**

**恢复：**

1. 打开 https://supabase.com/dashboard → 项目 kebiaoplan  
2. 点击 **Restore project**  
3. 等 1～3 分钟  
4. 服务器 **不用改** DATABASE_URL  
5. 打开 IP 测 fzh 登录  

**预防：** 每 2～3 天登录用一次；或每周备份时顺便登录。

## 八、备份（重要）

### 方式 A：Supabase 控制台（推荐新手）

Project Settings → Database → 按界面导出/备份

### 方式 B：命令行（本机，需 DATABASE_URL）

```bash
# 安装 pg_dump 后（或使用 Supabase 提供的连接串）
pg_dump "你的DATABASE_URL" -f backup-kebiaoplan-$(date +%Y%m%d).sql
```

**原则：**

- 每周至少 1 份  
- 备份文件 **不要提交到 Git**  
- **删表 / 迁库 / 大改前** 必须先备份

## 九、.env 必备项（服务器 `/var/www/plan/.env`）

| 变量 | 作用 |
|------|------|
| `AUTH_SECRET` | 登录 token 签名，改了全员要重登 |
| `ADMIN_USER` / `ADMIN_PASS` | 管理员 |
| `DATABASE_URL` | Supabase PostgreSQL，**别乱换** |
| `FEEDBACK_PUSHPLUS_TOKEN` | 反馈推微信（可选） |

改完必须：`pm2 restart kebiaoplan`

## 十、什么时候该紧张 / 什么时候不用

| 该紧张 | 不用紧张 |
|--------|----------|
| Supabase Paused 且用户在用 | 某一条 B 站链接解析失败 |
| 全部用户登录失败 | 一个人缓存问题 |
| 内存长期 > 85% | 页脚版本旧（强刷） |
| 准备删库、迁库 | 有人提新功能建议 |
| 备份超过 2 周没做 | 暂时不能用域名（备案） |
