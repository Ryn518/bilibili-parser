# 改代码后部署流程

> 本地改完 → 推到 GitHub → 服务器拉取构建重启。慌的时候只按这一页做。

---

## 一、本机（改代码并推送）

在项目目录 `d:\plan`（或你的本地仓库路径）：

```bash
cd d:\plan

# 1. 看改了哪些文件（可选）
git status

# 2. 提交
git add .
git commit -m "说明这次改了什么"

# 3. 推到 GitHub
git push origin main
```

**注意：**

- `git push` 必须成功，服务器才能拉到新代码
- 若出现连接 GitHub 超时：换网络 / 代理后再推，**不要**在 push 失败时就去服务器 `git pull`
- **不要**把 `.env`、数据库密码、备份 SQL 提交进 Git

---

## 二、服务器（拉取并上线）

腾讯云 WebShell（或 SSH）整段执行：

```bash
cd /var/www/plan
git pull origin main
npm install --legacy-peer-deps
npm run build
pm2 restart kebiaoplan
curl -s http://127.0.0.1:3000/api/health
```

期望：`curl` 返回类似 `{"ok":true}`，`pm2 status` 里 `kebiaoplan` 为 **online**。

然后浏览器打开 **http://kebiaoplan.cn**，按 **Ctrl+F5** 强制刷新，确认版本号和改动生效。

---

## 三、什么时候可以少做一步

| 情况 | 做法 |
|------|------|
| 只改了业务/前端代码（最常见） | 本机 push + 服务器全套（第二节） |
| 只改了服务器上的 `.env` | 不用 pull / build，只执行 `pm2 restart kebiaoplan` |
| `package.json` / 依赖没变 | 可跳过 `npm install`；不确定时照做更安全 |
| 只改文案或小 UI | 仍要 `npm run build` + `pm2 restart`（生产环境必须重新构建） |

---

## 四、红线（不要做）

- 不要删除或随意改服务器 `/var/www/plan/.env`（尤其是 `DATABASE_URL`、`AUTH_SECRET`）
- 不要在 Supabase 里删表、清空用户数据
- 不要在本机 `git push` 失败时，指望服务器能拉到新代码
- 不要把密钥、备份文件提交到仓库

---

## 五、出问题先查

```bash
# 进程是否在跑
pm2 status

# 最近日志
pm2 logs kebiaoplan --lines 50

# 本机应用是否活着
curl -s http://127.0.0.1:3000/api/health

# Nginx 是否转发到应用
curl -s http://127.0.0.1/api/health
```

更多排障见：`docs/项目维护一页纸.md`
